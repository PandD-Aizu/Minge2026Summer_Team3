## 何のために導入するか

この計画では、MCPを「CodexからローカルのUnity Editorを確認・操作するための接続」として扱う

利用目的は、Hierarchyやコンポーネントの確認、UIの配置、参照設定、Consoleの取得、画面キャプチャ、テストの補助
ゲームループの実装作業は [WorkPlan.md](WorkPlan.md) にまとめる

## 使う経路の案

### 第一候補: 既存のMCP for Unityを使う

```text
Codex → ローカルのMCP for Unityサーバー → Unity Editorのブリッジ → このプロジェクト
```

すでに登録されているパッケージを使い、最小限の設定で確認する案
同じリリースに対応したEditor側パッケージとサーバーを組み合わせる
HTTPかSTDIOかは、導入時に既存登録とパッケージの対応状況を確認して1つ選ぶ
HTTPを選ぶ場合は、同じPCからの接続を前提にローカルアドレスとポートを確認する
ポート番号やサーバー起動コマンドは推測で決めず、導入対象のパッケージと公式資料に合わせて記録する

MCP for UnityはEditor操作を提供する外部プロジェクトで、要件と機能は [開発元の案内](https://github.com/CoplayDev/unity-mcp) を参照する

### 代替候補: Unity PipelineとUnity CLIのMCPを使う

```text
Codex → Unity CLIのMCPサーバー → Unity Pipeline → このプロジェクト
```

Unity Pipelineは既存依存として登録されているが、CLIの所在と対応する版、使用できるEditorコマンドは未確認
第一候補で必要な作業を満たせない場合や、チームのUnity CLI運用に合わせる場合に検討する
現在の第一候補と同時に自動登録・自動起動することは計画の前提にしない

Pipelineの概要は [Unityのパッケージ資料](https://docs.unity3d.com/Packages/com.unity.pipeline@0.7/manual/index.html) を参照する

## Codex側の設定方針

CodexはSTDIOとStreamable HTTPのMCPに対応し、設定にはサーバーごとの無効化やツールの絞り込みがある
保存先や対応項目は [OpenAI公式のMCP資料](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) を基準に、導入時点のアプリで確認する

- 最初は対象プロジェクトに必要な接続だけを登録する
- ツール一覧を取得した後、実在する読み取りツールを選んで接続確認する
- 編集ツールは作業用シーンで確認してから、UI配置や参照設定へ使用範囲を広げる
- 個人の実行ファイルの絶対パスや認証情報を、チーム共通設定にそのまま入れない
- 自動設定機能が他クライアントの登録やネットワーク設定も書き換える場合は、変更内容を先に確認する

現在の文書は設定例を実ファイルとして配置しない
無効な登録を作る場合でも設定変更にはなるため、今回は `config.toml` やMCP設定ファイルを追加・更新しない

## ゲーム制作への使い方

| 使用場面 | MCPへ任せる候補 | ゲーム側に実装すること |
|---|---|---|
| 掟の画面 | Canvasやカードの配置、参照設定、画面確認 | 候補抽選、選択確定、違反判定 |
| 交換所 | 商品枠の配置、アイコン設定、表示確認 | 残高確認、所持品の追加・消費 |
| 自分の強化 | タブ、能力表示、素材枠の配置 | 費用計算、レベル更新、能力への反映 |
| 魚の調合 | 魚と薬のアイコン設定、演出確認 | 材料消費、薬の付与、使用と期限切れ |
| 動作確認 | Console取得、テスト実行、画面取得 | 成否を検証できるテストとゲーム状態の観測 |

MCPを導入しても、ゲームの処理やテストそのものが自動で完成するわけではない
まず読み取りと小さな編集が安定することを確認してから、制作の補助に使う

## 接続できない場合の調べ方

1. 対象プロジェクト、Editorの状態、コンパイルエラーを確認する
2. MCPサーバーとEditorブリッジのどちらで接続が止まっているか分ける
3. Pythonやサーバー側とEditor側の版の対応を確認する
4. HTTP方式なら、実際のアドレス・ポートとローカル接続の許可を確認する
5. 別の経路へ変更する必要があれば、一方を停止してから切り替える
6. うまくいかないときは追加した登録を戻し、試験用シーンの差分を確認する

今回の計画では、既存の接続を停止したり、すでに入っているパッケージを削除したりしない
