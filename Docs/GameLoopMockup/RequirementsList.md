# 必要なもの一覧

現在の統合モックをUnityへ組み込むための一覧
対象はチュートリアル18場面と通常の一日14場面で、ここではUnity側の完成を意味するチェックは付けない

## 最初に揃えるもの

| 分類 | 必要なもの | 用意の仕方 |
| --- | --- | --- |
| ゲーム背景 | 拠点、釣り場、昼・夕方・夜・明け方の見た目 | 既存シーンと照明・色調を使う |
| 登場するもの | 主人公、魚影、アジ、異形の魚、上位存在、ラジオ、集荷所 | 既存の素材・シーン内のものを再利用し、完成度を確認する |
| 共通UI | ウィンドウ、ボタン、スロット、お金アイコン | 新規4点が目安 |
| 掟のUI | 共通カード、掟のシンボル3種、確定済みの印 | 新規5点が目安　朝とチュートリアルの夜で共用する |
| 商品のUI | 釣り餌、お守りのアイコン | 新規2点が目安　たいまつは既存の仮素材を使用する |
| 強化のUI | 釣りの腕、足腰、集中力のアイコン | 新規3点が目安 |
| 調合のUI | ポーション、気配消し効果のアイコン | 新規2点が目安　材料のアジは既存画像を使う |
| テキスト | ラジオの会話、主人公の台詞、掟、ノルマ、商品・能力・薬の説明 | モックの仮文を確認して確定する |
| 設定データ | 掟3種、商品3種、能力3種、調合レシピ1種、ノルマ | 数量・価格・効果・期限をデータで設定する |

新規画像は合計16点が目安
ウィンドウ枠やボタンをUI機能で作る場合は、画像の制作点数を減らせる
素材ごとの詳細は [グラフィック素材リスト](GraphicsAssetList.md) を参照

## 見た目について決まっていること

- 掟選びはチュートリアルと通常の日で共通の画面にする
- 通常は朝に選び、チュートリアルの初回だけ帰還後の夜に選ぶ
- 掟確認・交換所・強化は、ゲームの背景と日時・場所を残してUIとして開く
- 朝用・夜用にカードを別々に描いたり、メニューごとに専用の背景イラストを作ったりする必要はない
- ノルマの表示は共通ウィンドウとテキストを使い、専用の一枚絵は必須にしない

## ゲームとして必要な処理

- [ ] 初回の案内から昼の釣り、夜の釣り場への移動まで接続する
- [ ] 初めての夜に上位存在と遭遇し、釣らずに撤退できるようにする
- [ ] 初回撤退では夜の釣果を増やさず、同じ夜の拠点へ戻す
- [ ] 帰還後の会話でノルマを提示し、数量・期限・納品状況を管理する
- [ ] 夜に掟を3つから選び、確定した後に交換所へ進める
- [ ] 共通の掟確認・購入・売却・能力強化・魚の調合・薬の使用を接続する
- [ ] 昼の魚を売却か調合に使い、同じ魚を二重に消費できないようにする
- [ ] 所持金と材料の不足、強化上限、薬の重ねがけを制御する
- [ ] メニュー操作中の入力と、探索・釣りの入力を切り替える
- [ ] 強化後に再出発し、夜の釣り場へ再到着したらチュートリアルを区切る
- [ ] 通常の日は毎朝掟を選び、昼釣り・帰還・交換・強化・夜釣り・翌朝をつなぐ
- [ ] 日付と期限を管理し、朝に掟と使用中の一時効果を切り替える
- [ ] お金・所持品・能力強化を翌日やシーン移動後にも保持する
- [ ] セーブ・ロードと、一周の動作確認を行う

細かい担当分けと完了条件は [必要な実装・制作作業](WorkPlan.md) を参照

## 後から仕上げるもの

- 遭遇時の暗転・警告、逃走、帰還時の息切れなどの演出
- 釣り、会話、購入、売却、強化、調合、薬の使用、危険を知らせる音
- 必要なら、すり鉢・すりこぎ、魚をすりつぶす演出、薬を飲む動作
- 選択・決定・成功・効果中の見た目と音の調整

これらは既存素材でどこまで表現できるか確認し、不足するものだけ追加する

## 実装前に決めること

- ノルマの数量・期限・納品方法・未達成時の扱い
- 掟の候補を固定にするか抽選するか、違反条件と結果
- 通貨名、初期所持金、売値・買値・強化費用
- 能力強化の実際の効果と上限
- 気配消しを敵のどの判定に反映し、いつ効果を解除するか
- メニューや会話中に時間を止めるか、捕獲・中断からどこへ戻すか

「魚1匹を翌朝までに納品」「アジ1匹で薬1本」「見つかりやすさ30%低下」などの数値は、現在はモックの仮案
MCPの準備は [導入計画](MCPIntegrationPlan.md) を参照し、ゲーム実装とは別に進める
